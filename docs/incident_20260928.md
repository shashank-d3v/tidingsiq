## Archive contract

`archive_bronze_incremental.py` exports rows in `[checkpoint, UTC midnight - 45d)`.
Each run acquires a generation-conditional GCS lock, creates an expiring immutable
BigQuery staging table, exports to a unique Parquet path, compares the entire row
multiset, writes an immutable manifest, then advances the checkpoint. Repeated
runs skip the completed range. Readers use the bootstrap index and follow the checkpoint's manifest chain;
failed exports and uncommitted manifests are not part of the committed archive.
Skip zero-row/no-op manifests when reading Parquet; those runs intentionally
create no data objects.
The immutable `automated/bootstrap.json` separately indexes the initial recovery
export. Restoration reads that bootstrap index plus the committed manifest chain.
The original rollout manifest predates predecessor links, so the bootstrap index
is required; never rewrite existing checkpoints to invent history.

Every source replacement and backfill MUST get a fresh `ingested_at`. Direct
historical in-place mutations require separate archival reconciliation. A crashed
worker leaves a lock and fails closed; confirm its execution has stopped before
removing that exact object generation. Staging tables expire after two days.
Archive objects retain the existing 365-day lifecycle; this is not permanent
historical retention. Exported archives may contain historical versions replaced
by later ingestions: restoration must deduplicate by source_record_id and newest
ingested_at, then reapply any metadata migrations.

Optional pruning is separate from export. It requires a verified checkpoint,
retains at least 90 days, and protects rows whose publication date is still inside
Silver's 90-day horizon. Default deletion cap is 20,000 rows; a transaction
rechecks it. Automatic approval review required explicit approval for the 445,596-row
catch-up removal. The user approved that exact removal on September 28; the
capped transaction and subsequent validation are recorded below.

## Long-term cost controls and remaining architecture

1. Keep the 90-minute source buffer and bounded asset retries. Keep whole-pipeline
   retries disabled. Investigate genuine missing archives rather than suppressing
   completeness alerts. The repair helper stages up to 31 daily sample windows
   and performs one bounded merge; it aborts before merge on any incomplete window.
2. Run checkpointed archives twice daily and alert on the first failure or 23.5 hours
   without a successful heartbeat. The authorized 90-day hot retention is enabled.
   Do not use 45-day deletion: Silver explicitly serves a 90-day horizon.
3. Retain typed monitoring. For higher volume, add a committed per-attempt summary
   table, including empty and failed attempts, and migrate Bronze to a stable
   source-date partition with explicitly pruned merges. These deeper migrations
   remain future work; they are not prerequisites for the deployed scan reduction.
4. Streamlit's persistent WebSocket creates ongoing active-use CPU charges even
   on request billing. A predictable low-cost public portfolio should ultimately
   publish a daily static feed/analytics snapshot and filter it in the browser,
   retaining Streamlit for on-demand analysis. This frontend migration is proposed,
   not deployed. Simply shortening WebSocket timeouts causes reconnections and
   does not solve the cost. Close unused dashboard sessions in the meantime.
5. Choose a monthly INR budget and usage alerts separately from hard service caps.
   A budget notification does not stop billing. Never promise a zero bill or pay
   an outstanding balance automatically.
